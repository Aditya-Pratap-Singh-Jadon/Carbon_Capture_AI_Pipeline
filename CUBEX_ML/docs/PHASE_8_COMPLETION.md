## Architecture
```
Temporal Process Sequence -> Temporal Encoder (LSTM) -> Latent Process State
Latent Process State -> EPINN Backbone -> 15 Physics Quantities
15 Physics Quantities -> Static Residuals -> Augmented Lagrangian -> Validation
```

## Sequence Design
The `SequenceBuilder` utilizes `pandas` sorting mechanisms looking for explicit `timestamp` or `iteration` columns (auto-detecting if required). It generates causal sliding windows of configurable length `W`, dynamically zero-padding earlier observations using steady-state padding (repeating the first observed index) to absolutely guarantee zero future-to-past temporal leakage.

## Temporal Variables vs Static Variables
Dynamic elements like `FC_actual`, `EC_actual`, `M_captured`, `P_fan`, `P_pump`, `eta_purity`, and `H_recovered` explicitly vary within the temporal sequences generated by the new synthetic regimes, representing thermodynamic and mechanical inertia. Administrative and fundamental constants (`NCV`, `EF_grid`, `F_SME`) are preserved statically. `F_valid` and `CC_T` remain strictly excluded from input models, only ever produced downstream via deterministic post-processing.

## Temporal Loss
Per the specific user correction: the proposed simple $||\frac{d\hat{y}}{dt}||^2$ temporal rate-of-change penalty was **rejected** and NOT implemented, because rapid legitimate fan-speed adjustments should naturally result in large, physically valid shifts in flow and capture without artificial penalty. Since the existing mathematical specifications do not contain differential equations, `l_temporal` was implemented purely as a placeholder hook (`0.0`). The system effectively uses the temporal history via the LSTM to better estimate the *current* 15 static physical states and minimize the 15 standard residuals.

## Tests & Results
The test suite expanded to 35 fully-passing tests.
- **Pointwise backward compatibility**: The pipeline successfully executes `model_config.json` files lacking `temporal_window_size`, correctly operating in 2D array mode, evaluating existing `test_adversarial.py` cases perfectly.
- **Leakage Prevention**: Tests confirm the final slice of `X_seq[i, -1, :]` corresponds cleanly to `df_sorted.iloc[i]` without look-ahead.
- **Transient Tests**: Demonstrated that a legitimate operation step (fan RPM driving a flow and mass captured spike) does not intrinsically fail `VerificationEngine`, whereas a disjointed step (e.g. sensor bias driving RPM up without flow matching) correctly triggers structural physical inconsistencies downstream.

## Known Limitations
The most significant limitation remains the **lack of a formalized temporal differential specification**. The E-PINN now has the structural capacity to observe time-series data and embed history, but until physical differential equations (e.g., thermal inertia transfer rates, solvent flow-rate-delay dependencies) are mathematically modeled in the project specification, the `l_temporal` component cannot actively penalize physical inconsistencies strictly in the time domain; it relies exclusively on the subsequent instantaneous static physical validations catching the discord.
